# AlgoPrep AI
https://algoprep-ai-zeta.vercel.app

An AI-powered DSA study companion. Enter a Data Structures and Algorithms topic (or paste your own notes) and AlgoPrep AI turns it into interactive **flashcards** and a **multiple-choice quiz**, generated by Google Gemini and validated before anything reaches the screen.

Built as a Frontend Developer Internship assignment. The main focus is reliable handling of unpredictable AI output.

## Features

**Generation**
- Enter any topic or paste study notes (3 to 4000 characters).
- Choose a mode: Flashcards, Quiz, or Both.
- Choose a difficulty: Mixed, Easy, Medium or Hard.
- Cancel a request in progress, and retry after a failure.

**Flashcards**
- Click to flip between question and answer.
- Previous / Next navigation and a progress indicator.
- Rate each card Easy, Medium or Hard (only after revealing the answer).
- Retest only the cards you rated Hard, or restart the whole deck.

**Quiz**
- Four-option multiple choice, one correct answer.
- Submit an answer, then see correct/incorrect feedback and an explanation.
- Final score and percentage accuracy, with a review list of missed questions.
- Retry only the incorrect questions, or restart the quiz.

**Persistence (localStorage)**
- Every generated study session is saved automatically.
- Flashcard ratings, quiz scores and incorrect questions are saved per session.
- Reopen any saved session later; delete sessions you no longer need.
- Dashboard stats (topics studied, quiz accuracy, cards rated easy) are computed from saved data.

**UX**
- Responsive layout for desktop, tablet and mobile (slide-in navigation drawer on small screens).
- Loading, error, retry and empty states throughout.
- Keyboard-accessible controls and visible focus states.

## How it works

```
React UI ──(Axios, POST /api/generate)──▶ Express ──(@google/genai)──▶ Gemini
   ▲                                         │
   │        validated JSON only              │ 1. validate request (Zod)
   └─────────────────────────────────────────┘ 2. call Gemini with JSON schema
                                               3. parse + validate output (Zod)
                                               4. add ids, validate final shape
```

1. The frontend sends `{ topic, mode, difficulty }`.
2. The backend validates the request, builds a prompt, and asks Gemini for JSON that matches a schema.
3. The AI output is parsed and validated with Zod. Anything malformed is rejected, not repaired.
4. The server (not the AI) assigns ids, then validates the final response once more.
5. The frontend validates the response again before rendering. The API key never leaves the server.

## Getting started

### Prerequisites
- Node.js 20 or newer and npm
- A Gemini API key from [Google AI Studio](https://aistudio.google.com/apikey)

### 1. Clone and install

```bash
git clone <your-repo-url>
cd algoprep-ai

cd backend
npm install

cd ../frontend
npm install
```

### 2. Configure environment variables

Create `backend/.env` by copying the example:

```bash
cd backend
cp .env.example .env        # on Windows PowerShell: Copy-Item .env.example .env
```

Then edit `backend/.env` and set your key.

| Variable | Required | Default | Description |
|---|---|---|---|
| `GEMINI_API_KEY` | yes | none | Your Gemini API key. Never commit it. |
| `GEMINI_MODEL` | no | `gemini-3.5-flash-lite` | Primary model. |
| `GEMINI_FALLBACK_MODEL` | no | none | Used only after the primary reports it is overloaded (HTTP 503). |
| `PORT` | no | `5000` | Backend port. |
| `CLIENT_ORIGIN` | no | `http://localhost:5173` | Allowed CORS origin. |
| `AI_TIMEOUT_MS` | no | `45000` | Overall deadline for one `/api/generate` request, retries included. |

Frontend (optional): set `VITE_API_URL` in `frontend/.env` if the backend is not at `http://localhost:5000`.

> Model availability and capacity change over time. If you see "model not found" or frequent 503 errors, run `node scripts/pingGemini.js` in `backend/` to list models and measure latency, then update `GEMINI_MODEL`.

### 3. Run

Terminal 1 (backend):
```bash
cd backend
npm run dev
```

Terminal 2 (frontend):
```bash
cd frontend
npm run dev
```

Open http://localhost:5173.

### Other commands
```bash
cd frontend
npm run lint     # ESLint
npm run build    # production build
```

## API

### `POST /api/generate`

Request:
```json
{ "topic": "Binary search trees", "mode": "both", "difficulty": "mixed" }
```
- `topic`: string, 3 to 4000 characters
- `mode`: `"flashcards"` | `"quiz"` | `"both"`
- `difficulty`: `"easy"` | `"medium"` | `"hard"` | `"mixed"` (optional, default `"mixed"`)

Success (`200`):
```json
{
  "success": true,
  "data": {
    "title": "Binary Search Trees",
    "mode": "both",
    "difficulty": "mixed",
    "flashcards": [
      { "id": "…", "question": "…", "answer": "…", "difficulty": "easy", "topic": "Binary Search Trees" }
    ],
    "quiz": [
      {
        "id": "…",
        "question": "…",
        "options": ["…", "…", "…", "…"],
        "correctAnswer": 2,
        "explanation": "…",
        "difficulty": "medium"
      }
    ],
    "generatedAt": "2026-11-15T10:30:00.000Z"
  }
}
```
`correctAnswer` is the zero-based index of the correct option. In `flashcards` mode `quiz` is `[]`, and vice versa.

Errors use one shape: `{ "success": false, "error": { "code": "…", "message": "…", "details": [...] } }`

| Status | Code | Meaning |
|---|---|---|
| 400 | `INVALID_REQUEST` | Input failed validation (`details` lists the fields) |
| 400 | `INVALID_JSON` | Request body is not valid JSON |
| 413 | `PAYLOAD_TOO_LARGE` | Request body over 100 kB |
| 429 | `RATE_LIMITED` | Gemini rate limit reached |
| 500 | `AI_CONFIG_ERROR` / `SERVER_MISCONFIGURED` | Bad API key, missing key or wrong model name |
| 502 | `AI_BAD_RESPONSE` | AI output was malformed or failed validation, even after retries |
| 502 | `AI_EMPTY_RESPONSE` | AI returned nothing, even after retries |
| 503 | `AI_UNAVAILABLE` | Gemini is overloaded or unreachable |
| 504 | `AI_TIMEOUT` | The request exceeded the time limit |

## Handling unreliable AI output

| # | Problem | How it is handled |
|---|---|---|
| 1 | Malformed JSON | Code fences are stripped, `JSON.parse` is wrapped in try/catch, and the call is retried (up to 3 attempts in total). Then a clean `502 AI_BAD_RESPONSE`. |
| 2 | Wrong structure | Zod validates the AI output (and again after ids are added). A failing response is rejected, never partially rendered. |
| 3 | Missing required fields | Required fields are enforced in the Gemini JSON schema and by Zod (4 options, answer index 0 to 3, unique options, non-empty text, array sizes). |
| 4 | Empty responses | Detected explicitly (`AI_EMPTY_RESPONSE`) and retried. |
| 5 | API failures | Upstream errors are mapped to meaningful statuses. Overloaded (503) responses are retried with a short backoff and an optional fallback model. |
| 6 | Rate limits | Mapped to `429` with a clear message. Not retried automatically, since retrying makes limits worse. |
| 7 | Slow responses / timeouts | An `AbortController` deadline on the server, a longer Axios timeout on the client, and a Cancel button in the UI. |
| 8 | Duplicate submissions | Controls are disabled while loading, and the request hook ignores new requests while one is in flight. |
| 9 | Stale responses | Each request gets an incrementing id and an `AbortController`. A response that is no longer the latest (cancelled or superseded) is discarded. |
| 10 | Invalid user input | Validated on the client (length limits) and again on the server with Zod, returning field-level error details. |

Additional safeguards:
- The server assigns ids, so the AI can never produce duplicate or missing ids.
- The frontend validates server responses and localStorage contents with the same kind of schema. A corrupt saved session is dropped instead of crashing the app.
- The prompt marks user input as data (`<user_input>`) to reduce prompt-injection effects.
- The API key lives only in `backend/.env` and is never sent to the browser.

## Persistence

Study sessions are stored in `localStorage` under the key `algoprep:sessions:v1` (maximum 20 sessions, newest first). Each entry holds the full study set, flashcard ratings, and quiz progress (rounds completed, latest full-quiz score, ids of questions still answered incorrectly). Data is validated when read; invalid entries are discarded. No account or database is needed.

## Testing

There is no automated test suite yet (see limitations). The following is how I verify the app.

Backend, from `backend/` with the server running:
```bash
node scripts/testGenerate.js ok            # full generation, both modes
node scripts/testGenerate.js quiz          # quiz only, hard difficulty
node scripts/testGenerate.js flashcards    # flashcards only
node scripts/testGenerate.js empty-topic   # expect 400 INVALID_REQUEST
node scripts/testGenerate.js bad-mode      # expect 400 INVALID_REQUEST
node scripts/testGenerate.js bad-json      # expect 400 INVALID_JSON
```
Failure paths I exercised: a very small `AI_TIMEOUT_MS` (504), a wrong API key (500), temporarily forcing malformed, structurally invalid and empty model output (502 after retries), and stopping the backend to see the network error state with retry.

Frontend: generate each mode, flip and rate flashcards, answer quizzes correctly and incorrectly, retry incorrect questions, refresh the page and reopen sessions, corrupt the localStorage value by hand, cancel and resubmit quickly, and check layouts at about 375px width.

## Known limitations

- **AI correctness:** the schema guarantees structure, not truth. A generated answer key or explanation can be wrong. A good next step would be a second verification pass or a "report this question" button.
- **No automated tests** (unit or end-to-end). Verification so far is manual.
- **No rate limiting or authentication on the backend**, so a public deployment could burn through API quota. Add `express-rate-limit` before deploying.
- **localStorage only:** data is per browser, not synced across devices or tabs, and limited to the 20 most recent sessions. If storage is full or disabled, the app keeps working but does not persist.
- A quiz round in progress is not saved; only completed rounds are.
- Study time is not tracked.
- The navbar search box, notifications button and Settings link are visual placeholders. The sidebar links scroll to sections of the dashboard.
- Input is text only (no file or PDF upload), and content is generated in English.
- Free-tier Gemini models can be slow or return 503 during busy periods; the retry and fallback logic reduces but cannot remove this.
